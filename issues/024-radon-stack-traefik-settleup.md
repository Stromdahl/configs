## Description

The keystone slice: **settleup reachable by a stranger at
`https://settleup.stromdahl.io`**, end-to-end through Cloudflare. This builds the
public stack every future radon app reuses — delivered as a new **`edge_stack`**
Ansible role — then runs settleup on top of it.

The `edge_stack` role mirrors the helium stack's render-and-up pattern (render the
compose file + env from templates, render Traefik's dynamic config, bring the stack
up) but **drops the two helium-specific pieces**: the NetBird mesh join and the
DOCKER-USER LAN-drop firewall rules — radon must be publicly reachable, not
mesh-restricted.

The plumbing this slice establishes:

- **Traefik** serving the static **Cloudflare Origin certificate** via its file
  provider (no ACME, no cert resolver), with the fleet's shared **security-headers**
  middleware plus a **rate-limit** middleware (the apps are unauthenticated). Traefik
  **trusts Cloudflare's IP ranges**, so the rate-limit keys on — and logs record —
  the real client IP rather than throttling Cloudflare collectively.
- The origin cert's **private key** stored **sops-encrypted for radon** under the
  existing admin-key host-vars rule (**no new sops rule**, and no per-host age key on
  radon), rendered to disk at `0600` by the role for Traefik to read. This key is
  radon's **only** at-rest secret.
- A **proxied (orange-cloud)** Cloudflare A record pointing `settleup.stromdahl.io`
  at radon, so the VPS IP stays hidden behind Cloudflare with SSL **Full (strict)**.

Then settleup itself: pulling its **pinned public GHCR image**, routed by Traefik at
`settleup.stromdahl.io`, `expose`-only (no host ports), configured via its documented
environment — bind all interfaces internally, and the `https://settleup.stromdahl.io`
base URL so QR/invite links and secure cookies come out right — with its **SQLite
database on a Docker named volume** on radon's local disk. **Only Traefik publishes
ports** (80/443); no app container publishes to the host, so Docker's iptables bypass
cannot inadvertently expose an app.

Depends on `issues/021` (the zone + origin cert), `issues/022` (radon provisioned as
the `edge` host), `issues/023` (the GHCR image to pull), and `issues/027` (the
multi-host `edge` play the stack role slots into).

## Acceptance criteria

- [ ] settleup loads at `https://settleup.stromdahl.io` with a valid certificate chain, through Cloudflare in Full (strict) mode.
- [ ] An invite link / QR generated by the deployed app uses the `https://settleup.stromdahl.io` base and opens on a phone.
- [ ] radon's real IP is not exposed in public DNS (the record is proxied); only 22/80/443 are reachable and only Traefik publishes ports.
- [ ] settleup's SQLite data survives a container restart (state lives on the persistent named volume).
- [ ] A rate-limit middleware and the shared security-headers are applied to the app's router; Traefik's logs/rate-limit show the real client IP, not a Cloudflare edge IP.
- [ ] The origin-cert key is sourced from sops (admin-key-only, no new rule; no per-host age key on radon) and rendered to disk for Traefik.
- [ ] A second playbook run reports **no changes** — the `edge_stack` role is idempotent.
