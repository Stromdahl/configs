## Description

The keystone slice: **settleup reachable by a stranger at
`https://settleup.stromdahl.io`**, end-to-end through Cloudflare. This builds the
public stack every future radon app reuses — delivered as a new **`edge_stack`**
Ansible role — then runs settleup on top of it.

The `edge_stack` role mirrors the helium stack's render-and-up pattern (render the
compose file + env from templates, render Traefik's dynamic config, bring the stack
up) but **drops the two helium-specific pieces**: the NetBird mesh join and the
DOCKER-USER LAN-drop firewall rules — radon must be publicly reachable, not
mesh-restricted.

The plumbing this slice establishes:

- **Traefik** serving the static **Cloudflare Origin certificate** via its file
  provider (no ACME, no cert resolver), with the fleet's shared **security-headers**
  middleware plus a **rate-limit** middleware (the apps are unauthenticated). Traefik
  **trusts Cloudflare's IP ranges**, so the rate-limit keys on — and logs record —
  the real client IP rather than throttling Cloudflare collectively.
- The origin cert's **private key** stored **sops-encrypted for radon** under the
  existing admin-key host-vars rule (**no new sops rule**, and no per-host age key on
  radon), rendered to disk at `0600` by the role for Traefik to read. This key is
  radon's **only** at-rest secret.
- A **proxied (orange-cloud)** Cloudflare A record pointing `settleup.stromdahl.io`
  at radon, so the VPS IP stays hidden behind Cloudflare with SSL **Full (strict)**.

Then settleup itself: pulling its **pinned public GHCR image**, routed by Traefik at
`settleup.stromdahl.io`, `expose`-only (no host ports), configured via its documented
environment — bind all interfaces internally, and the `https://settleup.stromdahl.io`
base URL so QR/invite links and secure cookies come out right — with its **SQLite
database on a Docker named volume** on radon's local disk. **Only Traefik publishes
ports** (80/443); no app container publishes to the host, so Docker's iptables bypass
cannot inadvertently expose an app.

Depends on `issues/021` (the zone + origin cert), `issues/022` (radon provisioned as
the `edge` host), `issues/023` (the GHCR image to pull), and `issues/027` (the
multi-host `edge` play the stack role slots into).

## Acceptance criteria

- [x] settleup loads at `https://settleup.stromdahl.io` with a valid certificate chain, through Cloudflare in Full (strict) mode.
- [ ] An invite link / QR generated by the deployed app uses the `https://settleup.stromdahl.io` base and opens on a phone. — base URL verified set (`SETTLEUP_BASE_URL=https://settleup.stromdahl.io`) and the site serves through Cloudflare; **opening a real invite/QR on a phone is the one remaining observational check (user).**
- [x] radon's real IP is not exposed in public DNS (the record is proxied); only 22/80/443 are reachable and only Traefik publishes ports.
- [x] settleup's SQLite data survives a container restart (state lives on the persistent named volume).
- [x] A rate-limit middleware and the shared security-headers are applied to the app's router; Traefik's logs/rate-limit show the real client IP, not a Cloudflare edge IP.
- [x] The origin-cert key is sourced from sops (admin-key-only, no new rule; no per-host age key on radon) and rendered to disk for Traefik.
- [x] A second playbook run reports **no changes** — the `edge_stack` role is idempotent.

## Resolution (2026-07-03)

Delivered as the new `roles/edge_stack/` (Traefik serving the static Cloudflare
Origin cert via the file provider — no ACME/CF-token; `rate-limit` +
shared `security-headers`; `forwardedHeaders.trustedIPs` = the current CF ranges
in `group_vars/edge.yml`; cert/key rendered to disk 0644/0600 from sops), the
settleup service (pinned `ghcr.io/stromdahl/settleup:sha-c8b9ac5`, expose-only,
`settleup_data` named volume at `/data`), `host_vars/radon/vars.yml`, and the
`site.yml` edge play. Mesh join, DOCKER-USER firewall, and `iptables-persistent`
were all dropped (ufw kept — see issues/028).

Verified on radon after `ansible-playbook site.yml --limit radon`:
- Through Cloudflare → **HTTP/2 200**, edge cert = Google Trust Services
  (`CN=stromdahl.io`); the 200 (not 526) proves **Full (strict)** validated the
  Origin cert end-to-end. Origin-direct (`--resolve … :2.24.160.184`) serves the
  **CloudFlare Origin CA** cert and settleup returns 200.
- Public DNS returns CF anycast only (origin `2.24.160.184` hidden); ufw active,
  default-deny, only 22/80/443; `docker ps` shows **only Traefik** host-publishes
  (80/443) — settleup/socket-proxy are expose-only; `iptables-persistent` absent.
- HSTS + frameDeny + nosniff + referrer/permissions-policy present; Traefik JSON
  access log records the **real client IP** (`ClientHost=90.224.150.73`), not a CF
  edge IP.
- `settleup.db` survives `docker compose restart settleup` (same inode/size on the
  named volume); origin key on disk is `0600 root:root`.
- **Second `--limit radon` run → `changed=0`** (idempotent).

One observational item remains for the user: open a real settleup invite link / QR
on a phone and confirm the `https://settleup.stromdahl.io` base (AC 2).
